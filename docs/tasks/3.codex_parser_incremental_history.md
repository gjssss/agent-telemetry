# Task 3: Codex Parser Incremental History

## 目标

实现 Codex session 扫描、隐私安全解析和基于 `history.json` 的增量上传判定。

## 并行关系

可与 `3.backend_upload_stats.md` 并行。

## 输入文档

- `docs/V1.md`
- `docs/TECH.md`

## 实现范围

- 默认扫描：
  - `~/.codex/sessions/**/*.jsonl`
  - `~/.codex/archived_sessions/*.jsonl`
- 解析 session 级聚合指标，只输出白名单字段。
- `session_id` 优先使用第一条 `session_meta.id`，文件名 UUID 作为校验或回退。
- token 总量取最后一个有效累计快照。
- `api_call_count` 按唯一 `total_token_usage` 累计快照数量计算。
- `conversation_turn_count` 按唯一 `turn_context.turn_id` 数量计算。
- `user_message_count` 按 `event_msg.type == "user_message"` 数量计算。
- `tool_call_count` 只统计工具调用数量，不上传参数和输出。
- 根据 `history.json` 判定新 session、变化 session、未变化 session。
- 仅在服务端确认上传成功后更新 history。

## 当前任务测试与校验

- 使用夹具 JSONL 测试解析结果，覆盖 token、turn、user message、tool call 计数。
- 测试重复 `token_count` 不会被按行累加。
- 测试输出对象不包含 prompt、response、reasoning、命令输出、项目路径、文件路径、git 信息或原始 JSONL。
- 构造 history 夹具，验证新文件会待上传。
- 修改 `file_size` 或 `file_mtime_ms`，验证会重新待上传。
- 未变化文件应跳过。
- 本地缺失但 history 中存在的 session 不应产生删除服务端数据的动作。
