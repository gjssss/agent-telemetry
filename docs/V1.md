# V1 Implementation Scope

## 任务目标

V1 要把当前模板仓库改造成 Agent Metry 的第一版可用产品：用户通过 CLI 上传本机 Codex session 的聚合消耗数据，并在自部署 Web 控制台中查看个人信息、使用概览和用户排行榜。

正式命令使用 `server`。模板仓库已有的示例功能不需要保留。

## 本期功能

### CLI

- `cli.js server`: 启动前后端一体服务。
- `cli.js config set/get/list/remove`: 管理本地配置，至少支持 `base_url`。
- `cli.js user create <email> <password>`: 创建用户，昵称默认等于邮箱。
- `cli.js login <email> <password>`: 登录并保存后续请求凭据。
- `cli.js upload`: 扫描 Codex session 并上传 session 级聚合数据。

上传默认扫描：

- `~/.codex/sessions/**/*.jsonl`
- `~/.codex/archived_sessions/*.jsonl`

上传使用 `login` 保存到本地的 token 鉴权，不上传 `user_id`。后端从 token 解析当前用户，并将 session 数据归属到该用户。`provider` 当前固定为 `codex`。

核心本地路径为 `~/.agent-metry`：

- `auth.json`: 登录时创建，存储 `access_token` 和 `refresh_token`。
- `config.json`: 首次 CLI 运行时创建并写入默认配置；当前包含 `base_url`，默认 `http://localhost:3000`。
- `data.db`: 首次运行 `server` 时创建并初始化。
- `history.json`: 记录已成功上传的 Codex session 文件状态，用于增量上传。
- `models.json`: 首次运行 `server` 时创建并写入默认模型价格表。

代码中需要提供 `configManager` 管理配置文件和字段。使用配置时，如果配置文件中读取不到目标字段，应直接报错。

`upload` 先扫描本机 Codex session：新 session 完整解析并上传；已记录但 `file_size` 或 `file_mtime_ms` 变化的 session 重新完整解析并上传最新聚合结果；已记录且文件未变化的 session 跳过。本地删除的历史 session 不影响服务端已有数据。

### 上传指标

- 基础维度：`provider`、`session_id`、`started_at`、`ended_at`、`model`、`model_provider`、`reasoning_effort`、`cli_version`、`model_context_window`。
- Token 指标：`input_tokens`、`output_tokens`、`cached_input_tokens`、`reasoning_output_tokens`、`total_tokens`。
- 行为计数：`api_call_count`、`conversation_turn_count`、`user_message_count`、`tool_call_count`。

实现必须使用白名单字段生成上传数据，不上传原始 JSONL、prompt、response、reasoning、命令输出、项目路径、文件路径和 git 信息。

### 后端

- 用户注册、登录、CLI 创建用户和昵称更新；昵称使用用户 `name` 字段。
- session 批量上传，并按登录用户派生的 `user_id + provider + session_id` 幂等 upsert。
- 后端根据 `models.json` 模型价格表计算费用。
- 模型价格缺失时上传和统计不能失败；前端需要提示管理员补充缺失模型 id 的价格。
- 支持信息页、排行榜、个人页所需统计查询。

### 前端

前端固定为 4 个用户可见页面：

- 登录页：复用模板登录页，删除 Provider Auth 按钮和 Terms/Privacy 文本；新增 Register 按钮。Register 默认开放，重复邮箱返回错误，注册成功自动登录，昵称默认等于邮箱。
- 信息页：主页面。顶部提供 `1d / 7d / 30d / total` Tab，下方展示费用、Token、Agent、模型和行为计数字段。
- 排行榜：顶部提供 `1d / 7d / 30d / total` Tab，子 Tab 为费用和 Token，下方用表格展示用户排行；空数据时显示空白表格。
- 个人页：展示个人信息，支持编辑用户昵称。

信息页、排行榜和个人页都作为主导航栏中的导航项。

## 测试与验收

- CLI：验证 `server`、`config`、`user create`、`login`、`upload` 主链路；确认 `auth.json`、`config.json`、`data.db`、`history.json`、`models.json` 的创建时机；重复 `upload` 不产生重复 session，未变化文件会跳过，变化文件会重新上传。
- 后端：使用 `curl` 验收健康检查、用户创建/注册、登录、上传、统计查询、排行榜和昵称更新。
- 前端：使用 agent-browser 验收登录页、信息页、排行榜和个人页，截图保存到 `/tmp`。
